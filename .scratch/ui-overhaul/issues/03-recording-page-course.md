## Agent Brief

**Category:** enhancement
**Summary:** `GET /videos/:id/play` says which Course Offering the video belongs to, and the recording page's back link uses it.

**Current behavior:**
`videoPlaybackSchema` has the video's id, title, YouTube id, embed URL, thumbnail, duration, resume point and `tracksProgress`, but nothing about the course. So the recording page's back link goes to "My courses" for students and "Home" for everyone else.

**Desired behavior:**
- The playback response adds `courseOfferingId` and `courseCode`.
- A student's back link is "Recordings", going to `/courses/$offeringId?tab=recordings`. Staff who teach the offering go to the teaching page's recordings tab if it has one, otherwise to the offering's teaching page. Anyone else goes to Home. The course code shows in the detail bar.
- Nothing else about playback changes. The entitlement rules stay as they are; a viewer who can't play the video still gets 404.

**Key interfaces:**
- `videoPlaybackSchema` gains `courseOfferingId: uuid` and `courseCode: string`.
- `useDetailBar` already takes `back: { to, label, params, search }` and `code`.

**Acceptance criteria:**
- [ ] The play response includes the offering ID and course code (integration test, for a student and for a Lecturer).
- [ ] The recording page's back link and course code follow the rules above.
- [ ] Typecheck, lint, unit, integration and budget checks pass.

**Out of scope:**
- An audio-only mode or lecture notes on the player.
