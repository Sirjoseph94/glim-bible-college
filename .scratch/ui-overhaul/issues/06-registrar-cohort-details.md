## Agent Brief

**Category:** enhancement
**Summary:** `GET /results/semesters` adds each student's level, the codes of their reopened course results, and a per-programme count of finalized courses. Transcript requests include the issued transcript's verification code.

**Current behavior:**
- The page groups `GET /results/semesters` rows into cohorts by programme code. Approve and publish act on a programme.
- A row has `draftCourseResults` (a count), but no level and no course codes.
- Nothing says how many of a programme's courses this semester have finalized results.
- `transcriptRequestSchema.transcript` is a summary without `verificationCode`; only the transcript's own page has it.

**Desired behavior:**
- Each row adds `levelNo` (from the semester enrollment) and `draftCourseCodes: string[]` (the course codes of the student's course results in the semester that are DRAFT, sorted).
- The response adds `courses: [{ programmeId, offerings, offeringsFinalized }]`, one entry per programme in the result. `offerings` counts the distinct Course Offerings that the programme's students in this semester are enrolled on. `offeringsFinalized` counts those whose every course result is no longer DRAFT.
- The cohort row reads "{programme} · Year {level}" (several levels: "Years 1–2"), shows "Courses finalized X of Y", and when waiting shows "Waiting on {codes}" (up to three, then "+N").
- `transcriptRequestSchema.transcript` adds `verificationCode`. The request list shows it in mono next to the serial.
- Grouping and the approve scope stay per programme.

**Key interfaces:**
- `semesterResultRowSchema.levelNo` and `.draftCourseCodes`
- The `listSemesterResults` response's `courses`
- `transcriptRequestSchema.transcript.verificationCode`

**Acceptance criteria:**
- [ ] The integration tests cover a reopened course result appearing in `draftCourseCodes` and lowering `offeringsFinalized`, the level on each row, and the verification code on an issued request.
- [ ] The page shows the level, "Courses finalized X of Y" and "Waiting on …" (component test or e2e).
- [ ] Typecheck, lint, unit, integration and budget checks pass.

**Out of scope:**
- Approving per level. The scope stays per programme.

**Built (2026-10-14), notes:** `levelNo` is nullable, because imported past results have no semester enrollment (the label then shows the programme alone). `courses` entries also carry `programmeCode`, because the page groups cohorts by programme code before the programme list has loaded. An offering counts as finalized only when every enrolled student has a non-draft course result, so an offering not finalized yet (no results) doesn't count. The cohort note reads "Waiting on GRK 301, PAS 210 · 2 students".
